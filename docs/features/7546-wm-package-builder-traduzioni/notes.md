## Bug trovati

- Nessun bug applicativo nuovo oltre a quello già in scope del ticket (Task 2, `json_decode` su colonna già castata `array`).
- PHPStan non eseguibile in questo ambiente locale per una race condition nella cache del container (`build/phpstan/cache`), indipendente dal codice di questa feature. Non bloccante: verificata solo la sintassi PHP (`php -l`) su tutti i file nuovi/modificati.
- **Trovato in review formale, corretto**: `TranslationsBuilder::fillAttributeFromRequest()` chiamava `json_decode()` assumendo che il payload fosse sempre una stringa. Una richiesta con notazione a bracket (`translations_builder[it]=...`, risolta da Laravel come array) avrebbe rilanciato lo stesso `TypeError` appena corretto in `AppConfigService` — stessa classe di bug, nuovo punto. Fix: guardia `is_string($raw)` prima di `json_decode`, più `is_array($payload)` esplicito dopo (invece di `?? []`, che non intercetta un JSON validamente decodificato in una stringa/scalare). Comportamento su JSON invalido reso esplicito: no-op silenzioso, coerente con il pattern già in uso in `RoleBooleanGroup`/`PermissionBooleanGroup` (vedi `AbstractUserResourceRoleGuardTest.php`, oc:8072) — non una scelta nuova, solo resa esplicita nel codice invece di implicita in un `??`. Aggiunti 2 test di regressione in `TranslationsBuilderTest.php`.

## Decisioni

- **Build del campo senza `laravel-nova-devtool`**: il pacchetto privato (richiesto per `mix.nova()`) non era installabile (credenziali scadute, fallback git via SSH non disponibile). Alternativa: `laravel-mix` + `vue` + `laravel-nova` (tutti pubblici su npm), con `webpack.mix.js` che imposta `externals: { vue: 'Vue' }` — altrimenti il bundle include una seconda copia di Vue in conflitto con quella reale di Nova, causando un rendering silenzioso del campo (nessun errore console, il tab appare semplicemente vuoto). `webpack` va pinnato **esatto** a `5.75.0` (non `^5.75.0`): versioni patch più recenti rompono la compatibilità tra `webpack-cli@4` (bundlato da `laravel-mix@6`) e il nuovo schema di validazione di `ProgressPlugin`.
- **Classi Tailwind "invisibili" nei campi custom**: nessun campo Nova custom del package ha una build Tailwind propria — si riusano solo le classi già presenti nel CSS compilato di Nova stesso. Qualunque classe Tailwind che Nova non usa da nessuna parte nella propria UI viene eliminata dal suo purge e non ha alcun effetto (scoperto empiricamente con `bg-opacity-50`, `px-5`, `gap-3`, `mb-1`/`mb-4`/`mb-5` — tutte silenziosamente senza effetto, causa di diversi round di correzioni CSS in questo ciclo). Vedi `wm-package/CLAUDE.md` per la regola pratica.
- **`<Teleport to="body">` obbligatorio per i modali**: senza, il modale (pur `position: fixed`) risultava disallineato orizzontalmente — quasi certamente per un `transform` in catena sui contenitori delle tab di Nova, che crea un containing block diverso dal viewport reale per gli elementi `fixed`. Pattern già presente in `FeatureCollectionMap.vue` in questo stesso package (non era stato riusato prima di questo ciclo solo perché non individuato subito) — confermato identico al `Modal.vue` nativo di Nova.
- **Componenti condivisi introdotti** (`src/Nova/Fields/_shared/resources/js/components/{Button,SelectInput,TextInput}.vue` + `src/Nova/Fields/_shared/resources/js/utils/collectAllKeys.js`, quest'ultimo aggiunto in review formale): verificato con ricerca dedicata che non esisteva alcun componente Button/Select/TextInput riutilizzabile tra i campi custom del package prima di questo ciclo. Le classi di `Button.vue` replicano esattamente quelle del `<Button>` nativo di Nova (`vendor/laravel/nova/resources/ui/components/Button.vue`, variante `solid`/`ghost`, size `large`) — garantite presenti nel CSS di Nova perché Nova le usa per i propri bottoni. Qualsiasi campo futuro può importarli con path relativo `../../../../_shared/resources/js/components/...` (o `.../js/utils/...`).
- **Niente paginazione nella tabella traduzioni** (richiesta esplicita di Giuseppe): scroll verticale interno (`max-height: 420px`) + colonna "Chiave" sticky orizzontale (larghezza massima fissa, testo a capo) con scroll orizzontale per le colonne lingua. Verificato manualmente con dataset di test da 100 chiavi × 5 lingue (it/en/fr/es/de, generati per il test — solo it/en persistono realmente a DB).

## Follow-up

- **Rischio noto, richiesto esplicitamente dal Task 9 del piano**: `upsertTranslation()` in `FormField.vue` — cuore della logica di merge condivisa tra form manuale e import file (Task 6/7) — **non ha copertura di test automatica**. Nessun test Vue (Vitest o altro) copre questa funzione; solo verifica manuale (Task 10). Un bug futuro in `upsertTranslation()` (es. l'upsert bulk sovrascrive la lingua sbagliata) non verrebbe intercettato da nessuna suite automatica. Mitigazione valutata ma non applicata in questo ciclo: `FeatureCollectionMap` nel package ha già un `vitest.config.cjs` funzionante che si sarebbe potuto riusare come base per testare `upsertTranslation()` isolatamente — rimandato a un ciclo successivo per limite di tempo, non per impossibilità tecnica.
- **Trovato in review formale, corretto**: `min-w-[220px]` era rimasta l'unica classe Tailwind "a valore arbitrario" nel file (le altre erano già state convertite a `style` inline per il problema del purge di Nova, vedi Decisioni) — convertita anch'essa in `style="min-width: 220px"`.
- **Trovato in review formale, corretto**: le celle lingua (`white-space: nowrap`, larghezza fissa sotto `table-layout: fixed`) non andavano a capo — un valore lungo senza spazi overflowava visivamente sovrapponendosi alla colonna successiva invece di espandere l'altezza della riga. Fix: `white-space: normal` + `overflow-wrap`/`word-break: break-word` su tutte le celle (non solo la colonna Chiave).
- **Trovato in review formale, corretto**: l'import JSON (Vue, `onFileSelected`) non faceva `trim()`/controllo vuotezza sulla chiave né validava il tipo dei valori come il form manuale. Fix: le entry importate vengono normalizzate (chiave `trim()`, scartate se vuota; valore accettato solo se stringa/numero/booleano, scartato se oggetto/array/null, coerciti tutti a stringa).

Estratta in `src/Nova/Fields/_shared/resources/js/utils/collectAllKeys.js` (funzione pura, non un componente Vue — stesso `_shared/resources/js` degli altri componenti condivisi), importata dai 3 file.
